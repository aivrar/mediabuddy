# AI Vision Florence-2

Media Buddy uses Florence-2 ONNX for local image captioning and object tags.

## What It Can Do

- Generate image captions.
- Generate object-derived tags.
- Fill missing captions.
- Replace short captions when explicitly configured.
- Add tags while preserving existing provider tags.

Vision currently supports image files, not video files.

## First Load

Florence-2 is not bundled inside the exe. Press **Load** in Settings to download
and cache model/runtime files in:

```text
data/models/
```

The first load can take time. Later loads reuse cached files.

## Runtime Downloads

The app can download runtime files used by ONNX Runtime:

- ONNX Runtime CPU from Microsoft GitHub releases.
- DirectML provider package from NuGet.
- CUDA provider package from NuGet.
- cuDNN runtime files from PyPI.

CUDA acceleration still requires compatible NVIDIA drivers and CUDA 12 runtime
DLLs available to Windows.

## Execution Modes

| Mode | Behavior |
| --- | --- |
| Auto | Prefer compatible GPU workers, use CPU only if selected/needed by fallback. |
| CUDA | Use NVIDIA CUDA workers when available. |
| DirectML | Use DirectML workers when available. |
| CPU | Use CPU workers only. |

## Worker Planning

Media Buddy detects available GPUs and estimates worker capacity from VRAM and
the configured reserved VRAM value. Florence-2 workers are separate loaded model
instances. Multiple workers allow more parallel image jobs.

Important settings:

- **GPU instances per GPU**: upper bound per compatible GPU.
- **Max total instances**: global upper bound.
- **Reserved VRAM (GB)**: memory left unused per GPU.
- **CPU instances**: number of CPU workers when CPU mode or fallback is used.
- **CPU threads per instance**: `0` means automatic runtime thread behavior.

## CPU Fallback

CPU fallback is for cases where GPU workers cannot be planned or loaded. If GPU
workers are successfully loaded in GPU mode, fallback CPU workers should not be
added just because the checkbox is enabled.

## Caption Safety

Every caption records who wrote it, and the library inspector shows it under
**Caption by**:

| Shown as | Meaning |
| --- | --- |
| provider | Came with the download from Pixabay, Pexels, or Unsplash. |
| AI (Florence-2) | Generated by an analysis run. |
| typed by hand | Edited in the inspector or set through the REST API. |
| not recorded | Saved by version 0.1.0, which did not track this, and the origin could not be worked out afterwards. |

Use the caption controls to choose what an analysis run may do:

- **Missing only**: fill empty captions.
- **Replace short**: also replace captions shorter than the configured length.
- **Overwrite**: replace captions.
- **Tags only**: leave captions alone and only add object tags.

Two protections sit on top of the mode, both on by default:

- **Keep manual**: a caption typed by hand is never replaced, in any mode.
- **Keep unknown**: a caption whose origin is "not recorded" is never replaced
  either. Nothing proves such a caption was not typed by hand, so replacing it
  has to be switched on deliberately.

Turn one off only if you want Replace short or Overwrite to replace those
captions too. Missing only and Tags only never replace an existing caption,
whatever these are set to.

When a run finishes, the summary says how many captions were kept by each
protection, for example "Captions kept: 2 typed by hand, 5 of unrecorded
origin".

### Captions With No Recorded Origin

Version 0.1.0 did not record who wrote a caption. When a newer version first
opens such a library it works out the origin where that can be proven, without
changing any text:

- If the caption still matches what the provider sent, it is marked
  **provider**.
- If it differs and the item was never AI analyzed, only a person can have
  changed it, so it is marked **typed by hand**.
- Otherwise it stays **not recorded**. This is typically a caption on an item
  that was AI analyzed: it may be the AI's text or a later hand edit.

For a "not recorded" caption the inspector offers **Mark as mine**, which
records it as typed by hand without changing it.

### Getting A Replaced Caption Back

Whenever an AI run replaces a caption, the old text is kept with the item. The
inspector shows it as **Replaced caption**, with its origin and a **Restore**
button. Restore swaps the two, so it can be undone, and no text is lost either
way. A second AI caption never pushes out a saved provider or hand-typed
caption.

It is safe to keep editing while a run is in progress. Each result is checked
against the item as it is at the moment the result is saved, so a caption or
tags saved during the run are kept, and object tags are added on top of the
current tag list rather than an earlier copy. Text typed in the inspector but
not yet saved is also left alone when a result arrives.

**AI analyzed** in the inspector means Florence-2 has processed the item. It
does not mean the caption is AI-written; **Caption by** tells you that.

## Unloading

The model cannot be unloaded while an analysis job is running; Unload reports
that it is busy. Jobs that are set to unload when they finish do so only once
no other job still needs the model.

## Troubleshooting Vision

- If DirectML reports unsupported feature level, try CUDA or CPU.
- If CUDA reports missing DLLs, install CUDA 12 runtime components or switch to
  CPU.
- If CUDA reports invalid resource handles, unload, restart the app, and try a
  lower worker count.
- If a model file hash mismatch is reported, delete `data/models/` and load
  again from a trusted network.
- If you switch runtime families after loading, restart the app. ONNX Runtime is
  process-wide and may not fully switch providers in one process.
